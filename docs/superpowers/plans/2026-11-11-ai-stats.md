# AI 判級準確率與花費統計 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把每次 AI 判定存成可標記的「判定紀錄」、把每次 AI 呼叫的用量存成「用量紀錄」，並新增 `/ai-stats` 統計頁（準確率＋樣本數、每月花費趨勢、判太嚴／判太鬆、各服務表）。

**Architecture:** 兩張新表 `ai_judgments`（判定＋標記，合併規則在 rpc 內原子執行）與 `ai_usage`（用量＋寫入當下算好的金額）。寫入點：`runTriager`（伺服器判級：判定＋用量）、`finishEvent` 的 `decision.kind === 'ci'` 路徑（CI 診斷判定）、新端點 `POST /api/ai-usage`（CI 用量）。所有寫入皆為旁路（try/catch＋console.error）。統計全部是 `src/core/ai-stats.ts` 純函式，頁面只負責撈資料與渲染。

**Tech Stack:** Next.js App Router（server component＋server action）、Supabase Postgres（service_role）、Vitest、Recharts `^3.9.1`、bash（curl/jq/openssl）。

**Spec:** `docs/superpowers/specs/2026-11-11-ai-stats-design.md`

## Global Constraints

- `src/core/**` 純函式：禁 I/O、禁 `Date.now()`／無參數 `new Date()`；時間一律由參數注入。
- Migration 流程：`supabase migration new <name>` → 編輯 SQL → `supabase db push` → `supabase db advisors --type security` → `pnpm db:types`。**禁用 MCP `apply_migration`**；`src/db/database.types.ts` 是自動產物，勿手改。
- 新表一律 `enable row level security` 且**不加任何 policy**（勿為了消 `rls_enabled_no_policy` INFO 加 policy）。rpc 函式 `security invoker`、`set search_path = ''`、revoke `public, anon, authenticated`、grant `service_role`（同 `upsert_issue_with_event`）。
- `pnpm test:integration` **只能**對本地 stack 跑（`supabase start` → `supabase db reset` → `pnpm test:integration`；OrbStack 需先開）。它會清空資料表，絕不可指向線上。
- 勿跑 `pnpm dev`，dev server 由使用者自管。套件管理用 pnpm。
- 單價（per MTok，USD）：`claude-sonnet-5-5` input **$2.00**／output **$10.00**。出處：claude-api skill「Current Models (cached: 2026-11-03)」價目表（Anthropic first-party API 價；同表 cache read $0.10，本專案兩條呼叫路徑皆未用 prompt caching，不計）。同表另列 `claude-opus-5-5` $4／$20、`claude-haiku-5-5` $0.10／$0.50（≤100K prompt）。單價常數**只**存在 `src/core/ai-pricing.ts` 的 `MODEL_PRICES`，換價改這一處；金額在寫入時算好存入，歷史金額不隨改價變動。
- 未登記單價的 model：照常記 tokens，`cost_usd` 為 NULL；統計頁必須顯示「有 N 筆未定價」，不得當成 0。
- 準確率一律與樣本數並列（例 `43／50 已標記`）；樣本數 0 時顯示「—」，不顯示 0% 或 100%。
- 準確率按**判定月份**（`judged_at`，台北時間）歸類，不按標記月份。月份界線用 Asia/Taipei（固定 UTC+8，無日光節約）。
- 用量／判定紀錄寫入失敗只能 `console.error`，不得讓判級、告警、心跳或 CI 失敗。
- `scripts/diagnose-e2e-failure.sh` 經 symlink／位元組一致複製給其他 repo：新 env 一律選填，未設時行為（輸出檔、exit code、stdout 以外的副作用）與現在完全相同。
- 圖表顏色只用 `app/globals.css` tokens：`--gold` 花費、`--green` 嚴重度準確率、`--pink` 類型準確率、`--lilac`／`--yellow` 其他系列、`--line` 格線與框線、`--fg`／`--fg-muted` 文字。不引入新色碼。
- commit 只 `git add` 明確路徑，禁 `git add -A`；不 push。

## Review Focus

1. **合併規則的邊界**：同一 issue 先 P1/app、再 P0/app、再 P1/app——第三筆要**新增**（只和「上一筆」比，不和更早的比）；且合併後沿用的是上一筆的標記。→ Task 2、3 測 `recordAiJudgment` 的 A→B→A 序列。
2. **PostgREST 1000 列上限**：統計頁撈 `ai_judgments`／`ai_usage` 若超過 1000 列會被靜默截斷，花費與準確率少算。→ Task 9 的 `fetchAllRows` 分頁，測「三頁」案例。
3. **判錯但正確答案等於 AI 答案／判錯沒選答案／判對卻帶答案**：server action 必須拒絕前兩者、清掉第三者的答案；DB check constraint 是最後防線。→ Task 1 單元測試＋Task 3 整合測試 constraint。
4. **`/api/ai-usage` 收到非法數值**：負數、小數 tokens、`NaN`、字串數字、`source: "server_triage"`（外部不得冒充伺服器判級）、`costUsd` 與 tokens 都缺——一律 422，不寫入。→ Task 5 payload 測試。
5. **CI 診斷只帶 `diagnosisError`、或 ingest 事件自帶 `severity` 但沒有 `metadata.diagnosis`**：不得產生判定紀錄（否則準確率分母灌水）。→ Task 4 pipeline 測試。

- [ ] **Step 1: 建 migration 並撰寫 SQL**

Run: `supabase migration new ai_stats`

SQL 要點（欄位名照寫，其餘自行補齊）：
- `ai_judgments`：`id uuid pk default gen_random_uuid()`、`issue_id uuid not null references issues(id) on delete cascade`、`service_id uuid not null references services(id) on delete cascade`、`source text not null check (source in ('server','ci'))`、`severity text not null check (in P0/P1/P2)`、`category text not null check (in env/app)`、`model text`、`judged_at timestamptz not null`、`last_judged_at timestamptz not null`、`merge_count int not null default 1`、`severity_verdict text check (in correct/wrong)`、`severity_correct text check (in P0/P1/P2)`、`category_verdict`、`category_correct`（同理）、`labeled_by text`、`labeled_at timestamptz`、`created_at timestamptz not null default now()`。
- 標記一致性 check（DB 最後防線）：
  ```sql
  constraint ai_judgments_severity_label_chk check (
    (severity_verdict is null and severity_correct is null)
    or (severity_verdict = 'correct' and severity_correct is null)
    or (severity_verdict = 'wrong' and severity_correct is not null and severity_correct <> severity)),
  constraint ai_judgments_category_label_chk check ( /* 同上，category */ )
  ```
- 索引：`(issue_id, judged_at desc)`、`(judged_at)`。
- `ai_usage`：`id uuid pk`、`service_id uuid not null references services(id) on delete cascade`、`source text not null check (in server_triage/ci_diagnosis/ci_pr)`、`model text`、`input_tokens int check (>= 0)`、`output_tokens int check (>= 0)`、`cost_usd numeric(12,6) check (>= 0)`、`occurred_at timestamptz not null`、`created_at timestamptz not null default now()`、`check (cost_usd is not null or (input_tokens is not null and output_tokens is not null))`；索引 `(occurred_at)`。
- 兩表 `enable row level security`，**不加 policy**。
- rpc `record_ai_judgment`：plpgsql、`security invoker`、`set search_path = ''`；先 `pg_advisory_xact_lock(hashtextextended('ai_judgment:' || p_issue_id::text, 0))`，再取該 issue `order by judged_at desc, created_at desc limit 1` 的一筆；severity 與 category 皆同 → `update set last_judged_at = greatest(last_judged_at, p_judged_at), merge_count = merge_count + 1` 回 `(id, true)`；否則 insert（`last_judged_at = p_judged_at`）回 `(new_id, false)`。revoke／grant 同 Global Constraints。
