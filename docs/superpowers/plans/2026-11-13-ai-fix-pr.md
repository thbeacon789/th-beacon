# E2E 失敗後由 AI 開修復 PR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trustnel iOS／Android 的每日 E2E 在判讀為 `category=app` 且 `needsCodeChange=true` 時，由獨立 CI job 內的 `claude -p` 改檔並開 PR 指派負責人；th-beacon 接收結果，在 Discord 討論串通知並在 issue 頁顯示 PR 連結，花費計入 `ci_pr`。

**Architecture:** 判讀腳本多輸出 `needsCodeChange` 與遮蔽後 log；`e2e-prod.yml` 新增唯讀的 `ai-fix` job 執行新腳本 `scripts/ai-fix-e2e-failure.sh`（去重 → 無 Bash 的 agent 改檔 → 越界檢查 → commit／PR → 回報）。th-beacon 新增 `POST /api/ai-fix`（route → handler → 純函式 payload 驗證 → Store），結果存在 `issues` 四個新欄位。伺服器不持有 Anthropic key 或 GitHub token。

**Tech Stack:** Next.js App Router、Supabase Postgres（service_role）、Vitest、bash（curl／jq／openssl／perl，相容 bash 3.2）、GitHub Actions、GitHub App、Claude Code CLI（`claude -p`）。

**Spec:** `docs/superpowers/specs/2026-11-13-ai-fix-pr-design.md`

## Global Constraints

- 套件管理 pnpm；**禁止** `pnpm dev`；`pnpm test:integration` 只對本地 stack（`supabase start` → `supabase db reset`），跑前先確認 `supabase status` 的 API URL 為 `127.0.0.1`，**絕不**對線上資料庫執行。
- `src/core/**` 為純函式（禁 I/O、禁 `Date.now`，時鐘由參數注入）。
- Schema 變更：`supabase migration new <name>` → 編輯 SQL → `supabase db push`（套用到線上）→ `supabase db advisors --type security` → `pnpm db:types`；**不得**用 MCP `apply_migration`；`src/db/database.types.ts` 為自動產物勿手改。
- 純 UI 改動只跑 `pnpm typecheck`，不跑 `pnpm test`。
- commit 一律明確路徑 `git add`；訊息結尾含 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`；任何 task 皆**不得** `git push`（push 須使用者明確要求；唯一例外是 Task 1 的臨時實驗分支，且須先取得使用者明確同意）。
- th-beacon 伺服器端不持有 Anthropic key 或 GitHub token；**不得**自行改用 `ANTHROPIC_API_KEY`，認證走既有 Anthropic WIF（GitHub OIDC）。
- 腳本只存在於 th-beacon `scripts/`；Trustnel 兩個 repo 在 workflow 執行時以 `actions/checkout@v4` ＋ deploy key（secret `BEACON_SCRIPTS_DEPLOY_KEY`）checkout 私有 repo `thbeacon789/th-beacon` 的**完整 40 碼 commit SHA**（`sparse-checkout: scripts`、`fetch-depth: 1`、`persist-credentials: false`），**不複製**進 App repo（2026-11-16 改版，spec §5.1／§5.5）。目錄配置：`playback-smoke` 為 App 在根、th-beacon 在 `.beacon/`（先 App 後 th-beacon）；`ai-fix` 為 App 在 `app/`、th-beacon 在 `beacon/`（並列）、腳本步驟 `working-directory: app`。釘選的 SHA 必須已存在於 th-beacon 遠端；更新腳本版本＝th-beacon push 後人工改兩個 repo 的 `ref`。
- 新腳本相容 bash 3.2（macOS）：不用關聯陣列、`mapfile`、`${var,,}`。
- 判讀腳本既有遮蔽（`DIAGNOSE_REDACT_VARS`）必須同樣套用在餵給修復 agent 的 log。
- agent 工具集合固定 `--tools "Read,Edit,Write,Glob,Grep"`（無 Bash、無網路）；預設 `AI_FIX_MODEL=claude-opus-5-5`、`AI_FIX_MAX_BUDGET_USD=5`、`AI_FIX_MAX_TURNS=40`、`AI_FIX_COOLDOWN_DAYS=7`；改動上限 20 個檔案／600 行；分支 `ai-fix/<heartbeat-name>`；PR 標題 `[AI fix] <prTitle>`、label `ai-fix`。
- 禁改清單（spec §5.3，逐字；命中任一即丟棄改動、狀態 `failed`）：
  - CI 與腳本：`.github/**`、`scripts/**`
  - 金鑰與簽章：`*.keystore`、`*.jks`、`*.p12`、`*.mobileprovision`、`.env*`、`**/google-services.json`、`**/GoogleService-Info.plist`
  - build 設定：`**/build.gradle*`、`settings.gradle*`、`gradle/**`、`gradle.properties`、`gradlew*`、`**/Package.swift`、`**/Package.resolved`、`**/*.xcodeproj/**`、`**/*.xcworkspace/**`、`Podfile*`、`**/*.xcconfig`
  - 不含 `/` 的 pattern（如 `*.jks`、`.env*`、`Podfile*`）比對任意深度的檔名；可由 env `AI_FIX_DENY_PATHS` 追加。
- 「commit 一律明確路徑」規範的是執行者在開發 repo 的 commit。修復腳本在 CI 一次性 checkout 內為 AI 的改動所做的 `git add --all` 與 commit 不在此限（該 commit 作者是 App bot，訊息不帶 Co-Authored-By）。
- `/api/ai-fix` status 三值 `pr_opened`｜`no_fix`｜`failed`；回應 `201 {issueId, notified}`、`404 unknown heartbeat`、`404 {error:"no_active_issue"}`，驗簽／格式錯誤沿用 401／400／422；`summary` 截斷 500 字。
- 溝通與文件用繁體中文；程式碼識別字維持原文。

## Review Focus

spec 隱含但容易漏的五類輸入／失效模式（各自的測試在所屬 task）：

1. `prUrl` 的仿冒網址（`https://github.com.evil.com/...`、`http://`、尾端 `/files`、帶 query、含 `)` 或空白）不得被接受或寫進 Discord／dashboard 連結 → Task 2、Task 5。
2. 回報到達時 issue 已 resolved、或同服務有別的心跳 → 一律 `404 no_active_issue`，不得誤寫到別筆 issue → Task 4。
3. `summary` 內含 `@everyone`、`<@id>`、`](` 時，Discord 訊息不得 ping 到負責人以外的人、不得形成可點的偽連結 → Task 4。
4. agent 改動的路徑含空白／非 ASCII／大小寫變體（`.GitHub/`）／以改名方式移入禁改目錄時，越界檢查不得被繞過 → Task 7a。
5. agent 失敗形態（超出預算的 `subtype`、非 JSON 輸出、缺 `total_cost_usd`、工作樹原本不乾淨、PR 描述含 `@mention`）不得讓腳本中止回報、洩漏提及、或把無關檔案 commit 進 PR → Task 7a、7b。
